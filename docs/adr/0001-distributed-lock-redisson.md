# ADR-0001: 分布式锁选型 Redisson

## 状态

已采纳

## 上下文

课程抢购场景下，多个用户同时预约同一课程可能导致库存超卖。需要一种并发控制机制。

## 决策

使用 Redisson 分布式锁，锁粒度为 `gym:booking:lock:{courseId}`。

## 理由

- 项目已有 Redis 依赖（Redisson starter），无需引入新中间件
- 分布式锁支持集群部署，比 `synchronized` 适用范围更广
- 按课程ID加锁，粒度适中，不同课程不互相阻塞
- `tryLock(3, 10, SECONDS)` 设置等待和持有时间，避免死锁

## 后果

- 依赖 Redis 服务可用性
- 锁粒度为课程级别，同一课程的所有用户串行抢购
- 未来如需更高并发，可考虑消息队列削峰
